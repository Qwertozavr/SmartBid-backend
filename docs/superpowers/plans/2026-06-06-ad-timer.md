# Ad Timer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a backend-owned 24-hour ad timer, terminal-state events, and a chat-authorized removal endpoint.

**Architecture:** The domain layer defines the ad State Machine, while `AdService` owns the fixed lifetime and current-time dependency. PostgreSQL performs conditional updates and claims expired ads with row locks; service transactions pair each terminal transition with an `ad.finished` outbox event. A minute-based worker invokes the completion use case, and the existing outbox dispatcher publishes both creation and completion events to Kafka.

**Tech Stack:** Go 1.22, PostgreSQL 16, pgx, goqu, Kafka, goose migrations, `net/http`

const AdStatusExpired AdStatus = "expired"

func (status AdStatus) CanTransitionTo(next AdStatus) bool {
	switch status {
	case AdStatusCreated:

	case AdStatusPublished:
